# 音频转 MIDI 工具

基于 Spotify 开源项目 [basic-pitch](https://github.com/spotify/basic-pitch) 与 Python 标准库 tkinter 构建的中文图形界面音频转 MIDI 工具。支持批量转换、多线程不卡界面、实时日志反馈和核心参数精细调节。

---

## 一、快速开始

### 运行

双击 `启动工具.bat`。脚本会依次寻找带有 tkinter 和 basic-pitch 的 Python 解释器（本机为 `C:\Python311\python.exe`）；若缺少依赖会自动安装。

也可以手动运行：

```bat
C:\Python311\python.exe "D:\AI workspace\audio2midi\audio2midi_gui.py"
```

> 注意：本机默认的 `python` 是 WorkBuddy 内置 3.13，**没有 tkinter**，不要直接用它运行本工具。推荐 Python 3.9–3.11（basic-pitch / TensorFlow 兼容性最好）。

### 转换流程

1. 点击「添加音频」，可一次选中多个文件（支持 wav / mp3 / flac / ogg / m4a / aac / aiff / opus / mp4 / webm）。
2. 选择输出目录；**留空**则每个 MIDI 输出到对应音频所在目录。
3. 选择参数预设，或手动调节下方参数。
4. 点击「▶ 开始转换」。过程中可随时「■ 取消」，日志面板实时显示每一步。
5. 完成后会弹出成功/失败统计；生成的 `.mid` 文件名与源音频同名。

## 二、核心参数详解

参数调节的基本思路：

> **先选预设 → 转一次 → 看日志里识别出的音符数 → 对照下面的"症状"微调 → 只改一个参数再转。**

所有阈值类参数都是**概率/能量阈值**：调高 = 更严格 = 识别出的音符更少、更保守；调低 = 更宽松 = 音符更多、更容易出现误识别。

### 1. 起音阈值 onset_threshold

| 默认值 | 可调范围 | 作用 |
|---|---|---|
| 0.50 | 0.05 – 0.95 | 判断"这里有一个新音符开始"的严格程度 |

- **调高（0.6–0.8）**：只有清晰、有力的起音才被识别。适合噪声大、有底鼓/鼓点误触发、或伴奏很强的录音；代价是弱奏、轻弹的音符会丢失。
- **调低（0.3–0.45）**：捕捉更多轻微起音。适合轻柔演唱、弱奏钢琴、指弹吉他；代价是把持续音的波动、呼吸声、鼓点误当成音符。
- **典型症状**：
  - MIDI 里出现大量短促杂音符 → 调高。
  - 明显能听到的音符没被识别 → 调低。

### 2. 音符帧阈值 frame_threshold

| 默认值 | 可调范围 | 作用 |
|---|---|---|
| 0.30 | 0.05 – 0.95 | 判断"这个音符还在持续"的严格程度 |

它和 onset 分工不同：**onset 决定音符在哪里开始，frame 决定音符持续多久**。

- **调高（0.4–0.6）**：尾部衰减快的声音会被提前截断，音符变短、变干净；适合电吉他、合成器、节奏紧凑的素材。
- **调低（0.15–0.25）**：音符持续更长、更容易连成一片；适合人声长音、弦乐、钢琴延音。过低会把噪声也延续成长音。
- **典型症状**：
  - 音符时长明显短于实际演唱/演奏 → 调低。
  - 相邻音符粘连成一条长音 → 调高。

**组合规律**：`onset 高 + frame 低` = 音符少但尾巴长；`onset 低 + frame 高` = 音符多但短促。两个参数建议一次只动一个。

### 3. 最短音符 minimum_note_length（毫秒）

| 默认值 | 可调范围 | 作用 |
|---|---|---|
| 127.7 ms | 30 – 1000 ms | 短于此时值的结果音符直接丢弃 |

- **调大（200–400 ms）**：过滤掉颤音、爆音、极短的误识别音符，结果更干净；但快速的装饰音、短促拨弦会被吃掉。
- **调小（50–100 ms）**：保留快速音符和密集音型；但容易留下大量碎音符。
- **典型症状**：
  - 满屏都是几毫秒的碎音符 → 调大。
  - 快速琶音/口播式旋律只剩几个音 → 调小。

### 4. 最低频率 minimum_frequency（Hz）

| 默认值 | 说明 |
|---|---|
| 0（不限） | 0 表示不施加下限过滤 |

作用是裁掉低频噪区：空调rumble、底鼓、贝斯低次谐波等。

- 人声：80–100 Hz
- 吉他：60–80 Hz
- 钢琴：30–40 Hz
- 环境噪声明显的录音：100 Hz 以上

> 设得太高会把贝斯线、低音区音符一并删掉。

### 5. 最高频率 maximum_frequency（Hz）

| 默认值 | 说明 |
|---|---|
| 0（不限） | 0 表示不施加上限过滤 |

作用是裁掉高频误识别：镲片、嘶声、齿音、电磁噪声。

- 人声：1000–1500 Hz
- 吉他：2000–3000 Hz
- 钢琴：4000–5000 Hz
- 纯旋律提取（不要泛音）：2000 Hz 左右

> 设得太低会丢掉高音区和泛音，声音听起来"闷"、缺高把位音符。

### 6. MIDI 速度 BPM（midi_tempo）

| 默认值 | 可调范围 | 作用 |
|---|---|---|
| 120 | 30 – 300 | 决定生成的 MIDI 采用的速度网格 |

**它不会改变音频速度，也不会伸缩时间**，只是把识别到的音符时间换算成 MIDI 节拍。设为源曲目的 BPM，导入 DAW / 打谱软件后才能与原曲对齐。

- 歌曲是 90 BPM 就填 90；不知道 BPM 可用在线测速工具估算。
- 只做音色试听、不关心同步时，保持 120 即可。

### 7. 音符力度 velocity（1–127）

basic-pitch 本身不输出有意义的力度，本工具在写出 MIDI 前统一给所有音符设置力度：

- **100（默认）**：通用值，DAW 里听起来自然。
- **调高（110–127）**：MIDI 音量更大、更"用力"，适合演示或驱动对力度敏感的音源。
- **调低（60–90）**：更轻柔，适合叠轨或避免削波。

> 这是**后处理**，不会影响识别结果，也不会还原原音频的强弱变化。

### 8. Melodia 后处理 melodia_trick

| 默认值 | 建议 |
|---|---|
| 开启 | 单旋律/人声建议开；和弦类乐器建议关 |

这是 basic-pitch 借鉴 Melodia 算法的后处理策略，倾向把结果"梳"成一条主旋律线：

- **开启**：人声、独奏、单音旋律更连贯，减少同时音和跳音。
- **关闭**：钢琴、吉他和弦、复音音乐更完整，能保留同时发声的多个音。

**典型症状**：弹和弦却只识别出单音 → 关掉；人声旋律里总混着多余的同度和弦 → 开启。

### 9. 多重弯音 multiple_pitch_bends

| 默认值 | 建议 |
|---|---|
| 关闭 | 吉他推弦、颤音、滑音建议开 |

- **开启**：允许时间上重叠的音符各自携带独立的弯音自动化，能保留推弦/fretless 滑音等细节；代价是 MIDI 事件更多、文件更大，部分老软件兼容性差。
- **关闭**：输出更简洁稳定；弯音细节会被合并/简化。

**典型症状**：吉他推弦在 MIDI 里变成一串阶梯式音符 → 开启；文件导入某些音源后表现异常 → 关闭。

## 三、预设与推荐组合

预设按钮只是快速填入以下参数，之后仍可手动微调：

| 预设 | onset | frame | 最短音符 | 频率范围 | Melodia | 弯音 |
|---|---|---|---|---|---|---|
| 通用 | 0.50 | 0.30 | 127.7 ms | 不限 | 开 | 关 |
| 人声演唱 | 0.45 | 0.25 | 110 ms | 80–1200 Hz | 开 | 关 |
| 吉他 | 0.55 | 0.35 | 130 ms | 60–2000 Hz | 关 | 关（推弦多可开） |
| 钢琴 | 0.50 | 0.30 | 90 ms | 30–5000 Hz | 关 | 关 |

## 四、调参速查表

| 现象 | 优先调整 |
|---|---|
| 杂音符太多、到处都是短音 | onset ↑；最短音符 ↑ |
| 明显的音没识别出来 | onset ↓；frame ↓ |
| 音符比实际短、断断续续 | frame ↓；最短音符 ↓ |
| 相邻音符粘成一长条 | frame ↑；最短音符 ↑ |
| 低频轰鸣被识别成音符 | 最低频率 ↑（80–100 Hz） |
| 高频嘶声/镲片被识别 | 最高频率 ↓（2000 Hz 左右） |
| 和弦只剩单音 | Melodia 关 |
| 人声里混进多余和音 | Melodia 开 |
| 推弦/颤音变成阶梯音符 | 多重弯音 开 |
| 导入 DAW 后与原曲对不上 | 把 BPM 设为源曲目速度 |
| MIDI 声音太小/太大 | 调整音符力度（不影响识别） |

## 五、实现说明

- **多线程**：模型推理、环境检测、pip 安装均在后台线程；主线程只负责界面，通过队列 + 100 ms 定时轮询更新日志、进度和状态，因此转换过程中窗口不会无响应。
- **模型复用**：`ICASSP_2022_MODEL_PATH` 对应的模型只加载一次，批量转换时供所有文件复用，避免重复加载开销。
- **日志反馈**：按文件输出进度与识别音符数；单文件失败会自动记录异常并继续处理下一个文件。
- **依赖安装**：界面「环境检测」按钮可检查 basic-pitch / TensorFlow / 模型文件；缺失时可在界面内一键后台安装。
- **注意**：basic-pitch 导入时控制台可能出现 TensorFlow 兼容性提示，属正常现象，不影响 GUI 与转换结果。
